# M04.2-A — Entorno aislado Pipecat

## Estado

El bloqueo Windows fue `WinError 32`: `onnxruntime` estaba retenido durante la instalación. No se finalizó ningún proceso ni se eliminó el entorno parcial. El runtime de voz se aísla ahora en una imagen Linux, sin modificar las dependencias de `energy-api`.

## Dependencias verificadas

- Python 3.12 Linux (`python:3.12-slim`, arquitectura de la plataforma Docker).
- `pipecat-ai[webrtc,openai]==1.14.0`.
- El extra oficial `webrtc` incluye SmallWebRTC/audio y `openai` añade los servicios OpenAI.
- El smoke test importa `SmallWebRTCTransport`, `OpenAISTTService`, `OpenAITTSService` y `OpenAILLMService`; no construye clientes ni realiza red externa.

## Arquitectura

    navegador (futuro WebRTC) -> voice-agent:7860 (sólo 127.0.0.1)
                                      | Bearer interno
                                      v
                                  energy-api:8000

`voice-agent` está bajo el perfil Compose `voice` y `VOICE_AGENT_ENABLED=false` por defecto. Sólo ofrece `/health`; el pipeline de voz todavía no existe. El valor de `VOICE_ENERGY_API_TOKEN` recibe el token privado de `energy-api` mediante Compose, sin persistirlo ni imprimirlo.

## Construcción y verificación

```powershell
docker compose --profile voice build voice-agent
docker compose --profile voice run --rm voice-agent python -m voice_agent.smoke_test
docker compose --profile voice up -d voice-agent
Invoke-WebRequest http://127.0.0.1:7860/health
```

No use `docker compose config` al compartir una consola: puede expandir secretos. El build correcto sólo verifica imports; no confirma micrófono, WebRTC, STT, LLM ni TTS.

## Limpieza manual del entorno fallido

1. Cierre procesos Python/Codex que retengan archivos del entorno.
2. Confirme con el Administrador de tareas antes de cerrar procesos ajenos.
3. Cuando no existan bloqueos, elimine manualmente `voice_agent/.venv`.

No se borra automáticamente porque Windows informó archivos en uso.
