# M04.6 — Runner persistente y sesiones autorizadas

El stack normal inicia `voice-agent` como proceso persistente. Su healthcheck
solo comprueba HTTP; no certifica ICE, WebRTC ni audio.

Para desarrollo con el runner directo de Windows en `:7861`, use:

```powershell
docker compose -f compose.yaml -f compose.windows-voice.yaml up -d --build energy-api
```

El navegador recibe `VOICE_PIPECAT_URL=http://127.0.0.1:7861`; desde
`energy-api` en Docker, la sonda HTTP usa `VOICE_RUNNER_HEALTH_URL=http://host.docker.internal:7861`.

`VOICE_PIPELINE_ENABLED=false` es el límite seguro inicial. Cuando el operador
lo habilita en API y runner, la UI puede solicitar una autorización temporal,
autenticada y de un solo uso para una sesión `ai`. El runner la valida contra
la API antes de construir proveedores. Seleccionar o deseleccionar IA solo
afecta la siguiente conexión y nunca reinicia el runner.
