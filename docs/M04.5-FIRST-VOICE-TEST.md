# M04.5 — Primera conversación de voz controlada

Este procedimiento usa el runner Pipecat local de Windows. No carga `.env`
automáticamente: las variables necesarias deben existir en la sesión de
PowerShell y nunca deben pegarse en comandos registrados o capturas.

## Preparación

Para que `/demo` use el runner Windows validado, inicie Compose con el override
local. La URL pública enviada al navegador es `127.0.0.1:7861`; la sonda de
`energy-api` usa `host.docker.internal:7861` desde Docker. No son intercambiables.

```powershell
docker compose -f compose.yaml -f compose.windows-voice.yaml up -d --build energy-api
```

1. Configure manualmente `ENERGY_TOOLS_API_TOKEN` y `OPENAI_API_KEY` en la
   sesión, sin imprimirlos.
2. Active el estado de pipeline para la demo y reinicie solo la API. Esto
   reinicia el snapshot en memoria, por lo que debe cargarse después.

```powershell
$env:VOICE_PIPELINE_ENABLED = "true"
docker compose up -d --build --force-recreate --no-deps energy-api
```

3. Abra `http://127.0.0.1:8000/demo`, ingrese el Bearer y cargue
   `Datos\vesta_snapshot_sintetico.json`. Confirme que la interfaz indique
   `DEMO` y que el estado del snapshot esté cargado.
4. En la misma sesión de PowerShell, prepare el runner. El token interno debe
   ser el mismo Bearer usado por `energy-api`; no se envía al navegador.

```powershell
$env:VOICE_AGENT_ENABLED = "true"
$env:VOICE_PIPELINE_ENABLED = "true"
$env:VOICE_ENERGY_API_BASE_URL = "http://127.0.0.1:8000"
$env:VOICE_ENERGY_API_TOKEN = "<Bearer local de Energy Tools>"
$env:OPENAI_API_KEY = "<clave configurada manualmente>"
$env:VOICE_STT_MODEL = "gpt-transcribe"
$env:VOICE_LLM_MODEL = "gpt-6-luna"
$env:VOICE_TTS_MODEL = "gpt-4o-mini-tts"
$env:VOICE_TTS_VOICE = "alloy"
$env:VOICE_MAX_TURNS = "3"
$env:VOICE_SESSION_BUDGET_USD = "0.20"
$env:VOICE_BUDGET_USD = "2.00"
$env:VOICE_MAX_SESSIONS = "10"
$env:VOICE_USAGE_FILE = "$PWD\data\voice-usage.json"
.\.venv\Scripts\python.exe -m voice_agent.webrtc_runner -t webrtc --host 127.0.0.1 --port 7861 --allowed-origins http://127.0.0.1:8000
```

`VOICE_PIPELINE_ENABLED=true` es el interruptor efectivo de la cascada. Antes
de construir STT, LLM o TTS, el runner reserva el monto completo de la sesión
en `VOICE_USAGE_FILE`. La reserva se cobra al cerrar incluso si una llamada
del proveedor falla, para no subestimar gasto. El archivo contiene solo
contadores y USD agregados; no conserva audio ni texto.

## Una prueba aprobada

1. En la pestaña **Asistente de voz** de `/demo`, marque **Usar agente IA de
   voz (Pipecat + OpenAI)** para esa sesión, conecte y otorgue permiso al
   micrófono. La autorización expira y no se reutiliza en otra conexión.
2. Pronuncie: “Vesta, ¿cuál fue el consumo energético total de 2025?”.
3. Compruebe el texto transcrito, la respuesta escrita y su reproducción de
   voz. En la consola de Uvicorn se debe observar el acceso autenticado a
   `GET /energy/overview?year=2025`; no inspeccione ni copie cuerpos de
   respuesta.
4. Desconecte. Revise solo los contadores agregados de
   `data\voice-usage.json` para confirmar una sesión completada y el gasto
   reservado, sin publicar ese archivo.

Una conexión que llegue a `CONNECTED` valida WebRTC. Una conversación válida
además muestra transcripción, respuesta de Vesta, audio de salida y la consulta
`/energy/overview` contra el snapshot DEMO activo.

## Límites y pendientes

- La API rechaza herramientas fuera de las seis autorizadas y argumentos no
  compatibles.
- La disponibilidad de la cuenta OpenAI solo se confirma en la prueba manual;
  esta guía no realiza una solicitud automática.
- `gpt-4o-mini-tts` funciona con el flujo Speech API existente, pero OpenAI lo
  marca como deprecado para enero de 2027. Mantener este alcance para la prueba
  y evaluar la migración por separado.
- La conectividad ICE/TURN dentro de Docker Desktop continúa siendo un asunto
  independiente. Este procedimiento usa el runner validado localmente en
  Windows.
