# M04.4 — Pipeline de voz Pipecat y Energy Tools

## Estado

`VOICE_PROVIDER=pipecat` usa SmallWebRTC y puede construir un pipeline
encadenado de Pipecat 1.14:

```text
Micrófono → OpenAI STT → contexto + seis Energy Tools → OpenAI LLM → OpenAI TTS → navegador
```

El pipeline está **deshabilitado por defecto** con
`VOICE_PIPELINE_ENABLED=false`. La conexión SmallWebRTC mínima de M04.3 sigue
funcionando cuando permanece deshabilitado. Esta separación permite validar el
transporte sin enviar audio ni datos a un proveedor.

## Herramientas y datos

`voice_agent.voice_pipeline` registra solamente `get_overview`, `get_store`,
`rank_stores`, `get_solar`, `get_chiller` y `get_data_info`. Sus argumentos se
validan antes de usar `VoiceEnergyAdapter`, que llama por HTTP autenticado a la
API existente. El runner no carga snapshots, Excel ni cálculos del dashboard;
el modelo recibe solo el resultado acotado de cada herramienta.

## Protección efectiva de costo

La reserva por sesión es persistente y conservadora: antes de crear los
servicios de proveedor, el runner reserva `VOICE_SESSION_BUDGET_USD`. Cuando
termina —incluso tras error— la reserva completa se carga al ledger. Por tanto,
`VOICE_BUDGET_USD` no puede superarse aunque un proveedor no devuelva uso
exacto. También se limitan sesiones y turnos. El ledger contiene solo totales;
nunca audio, transcripciones, prompts, resultados ni claves.

```text
VOICE_PIPELINE_ENABLED=false
VOICE_STT_MODEL=gpt-transcribe
VOICE_LLM_MODEL=gpt-6-luna
VOICE_TTS_MODEL=gpt-4o-mini-tts
VOICE_TTS_VOICE=alloy
VOICE_MAX_TURNS=3
VOICE_TOOL_TIMEOUT_SECONDS=10
VOICE_SESSION_BUDGET_USD=0.20
VOICE_BUDGET_USD=2.00
VOICE_MAX_SESSIONS=10
```

`gpt-transcribe` es el modelo recomendado para transcripción de archivos; el
pipeline usa el servicio streaming de Pipecat con el modelo configurado. La API
de texto a voz actualmente mantiene compatibilidad con `gpt-4o-mini-tts`, pero
OpenAI ha anunciado su deprecación; revisar la guía oficial antes de una salida
productiva. [OpenAI Voice agents](https://developers.openai.com/api/docs/guides/voice-agents)
describe el enfoque encadenado como STT, agente y TTS; [Text to speech](https://developers.openai.com/api/docs/guides/text-to-speech)
documenta la transición de modelos.

## Primera prueba manual controlada

1. Cargar únicamente el snapshot sintético y comprobar que el ledger de voz
   tiene presupuesto disponible.
2. En `.env` local, establecer `VOICE_PIPELINE_ENABLED=true` y una clave de
   OpenAI válida. No colocar la clave en archivos versionados.
3. Iniciar el runner Windows:

```powershell
cd C:\Users\Jona\Documents\Proyectos\voiceAI-energy-assistant
$env:VOICE_AGENT_ENABLED = "true"
$env:VOICE_PIPELINE_ENABLED = "true"
.\.venv\Scripts\python.exe -m voice_agent.webrtc_runner -t webrtc --host 127.0.0.1 --port 7861 --allowed-origins http://127.0.0.1:8000
```

4. Abrir `/demo`, cargar el JSON sintético, ir a **Asistente de voz**, conectar
   y formular una única pregunta breve: “¿Cuál fue el costo eléctrico de 2025?”.
5. Confirmar transcripción, llamada `get_overview(2025)`, respuesta con período
   y unidad, audio y desconexión. Revisar solo totales del ledger.
6. Volver `VOICE_PIPELINE_ENABLED=false` después de la prueba.

Esta prueba no fue ejecutada automáticamente. La conectividad Docker/TURN sigue
siendo un experimento separado y no forma parte del criterio de este hito.
