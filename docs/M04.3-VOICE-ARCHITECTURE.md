# M04.3 — Arquitectura de voz configurable

La cuarta pestaña **Asistente de voz** reutiliza la interfaz de Vesta y no
crea otro agente energético. El backend selecciona el proveedor mediante
`VOICE_PROVIDER`; el navegador solo recibe `GET /voice/config`, que contiene
estado, proveedor, límites y —solo para Pipecat— una URL local de señalización.
No contiene claves, token Bearer, snapshot ni configuración de OpenAI.

## Estado de proveedores

| Proveedor | Estado | Alcance |
| --- | --- | --- |
| `pipecat` | Implementado para conexión SmallWebRTC mínima | Micrófono, conexión y desconexión con el bundle oficial. El pipeline actual no incluye STT, LLM ni TTS. |
| `openai_direct` | Adaptador reservado | No expone controles ni realiza grabación, transcripción o síntesis hasta implementar límites de gasto específicos. |

El pipeline posterior debe usar `voice_agent.energy_api.VoiceEnergyAdapter`, que
llama por HTTP autenticado a las seis Energy Tools existentes. Nunca debe
copiar el snapshot a Pipecat ni recrear cálculos del dashboard.

## Configuración local

En `.env` local (no versionado):

```text
VOICE_ENABLED=true
VOICE_PROVIDER=pipecat
VOICE_PIPECAT_URL=http://127.0.0.1:7861
VOICE_MAX_SESSION_SECONDS=60
VOICE_MAX_RECORDING_SECONDS=30
```

`VOICE_STT_PROVIDER` y `VOICE_TTS_PROVIDER` pueden reservarse para el pipeline
futuro, pero M04.3 no los publica ni los consume. El servicio de Energy Tools
mantiene los límites y ledger del agente textual; una integración de audio no
puede eludirlos y requiere un presupuesto persistente explícito antes de
activar proveedores pagados.

## Prueba manual con runner Windows

Con el entorno Pipecat aislado ya preparado, iniciar el Development Runner:

```powershell
cd C:\Users\Jona\Documents\Proyectos\voiceAI-energy-assistant
$env:VOICE_AGENT_ENABLED = "true"
.\.venv\Scripts\python.exe -m voice_agent.webrtc_runner -t webrtc --host 127.0.0.1 --port 7861 --allowed-origins http://127.0.0.1:8000
```

En otra consola, reconstruir solamente la API y abrir Vesta:

```powershell
docker compose up -d --build --force-recreate --no-deps energy-api
Start-Process http://127.0.0.1:8000/demo
```

Abrir **Asistente de voz**, pulsar **Conectar** y conceder el permiso de
micrófono. El éxito mínimo se confirma cuando el estado es `Conectado` y el
runner registra `SmallWebRTC client connected`. **No prueba conversación**:
STT, LLM, Energy Tools y TTS siguen pendientes y no se inicia OpenAI en estas
instrucciones.

La alternativa Docker/TURN sigue siendo experimental en Docker Desktop para
Windows: sus experimentos se conservan en `compose.webrtc-local.yaml` y
`compose.webrtc-turn.yaml`, pero no son requisito de esta integración inicial.
