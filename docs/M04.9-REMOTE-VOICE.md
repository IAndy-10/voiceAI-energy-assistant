# M04.9 — Voz remota con Cloudflare Tunnel y Twilio TURN

## Alcance

Un colega en otra red abre un enlace `https://`, carga los `.xlsx`, ingresa la
clave y habla con Vesta. Los servicios siguen enlazados solo a `127.0.0.1`.

```
Navegador remoto ──HTTPS── Cloudflare Tunnel ──► 127.0.0.1:8000 (/app, API)
                 ──HTTPS── Cloudflare Tunnel ──► 127.0.0.1:7860 (señalización Pipecat)
                 ══SRTP═══ Twilio TURN ════════► voice-agent (aiortc)
```

- El túnel entrega HTTPS (requisito del micrófono) sin abrir puertos:
  `cloudflared` corre en el Mac y se conecta a loopback.
- El túnel transporta solo HTTP. El audio WebRTC (UDP) pasa por Twilio
  Network Traversal Service, que reenvía SRTP cifrado y no puede escuchar la
  sesión. El TURN local (`turn-local`) solo lo alcanza un navegador del mismo
  equipo.

Validado el 2026-11-04 desde un celular con datos móviles: ICE `completed`,
candidatos `relay` de Twilio, `get_overview` y audio con TTS OpenAI y
ElevenLabs. TTFB mediano: STT ~1,1 s, LLM ~0,7–1,3 s, TTS ElevenLabs ~0,2 s
(OpenAI ~1,3 s). El túnel y Twilio no sumaron una demora perceptible.

## Configuración

| Variable | Por defecto | Uso |
| --- | --- | --- |
| `VOICE_TURN_MODE` | `local` | `local` (coturn) o `twilio`. Otro valor impide iniciar el runner |
| `VOICE_ALLOWED_ORIGINS` | `http://127.0.0.1:8000,http://localhost:8000` | Orígenes exactos de `/app` que pueden abrir sesiones, separados por coma |
| `VOICE_PIPECAT_URL` | `http://127.0.0.1:7860` | URL del runner que recibe el navegador; en remoto, la del túnel de `:7860` |
| `TWILIO_ACCOUNT_SID` | — | Obligatoria con `twilio` (empieza con `AC`) |
| `TWILIO_AUTH_TOKEN` | — | Obligatoria con `twilio`. Compose la entrega solo a `voice-agent` |
| `VOICE_TURN_TTL_SECONDS` | `86400` | Vida de la credencial TURN, en coturn y en Twilio |

## Cómo funciona

- **`voice_agent/twilio_ice.py`** pide `POST /2010-04-01/Accounts/{SID}/Tokens.json`
  con `Ttl`, solo con la biblioteca estándar. Normaliza la respuesta para
  Pipecat 1.14, que rechaza cualquier clave distinta de `urls`, `username` y
  `credential` (Twilio también envía `url`), y deja TURN por UDP como primera
  URL TURN, porque aiortc usa solo esa.
- **Renovación sin reinicio.** `IceServerRefresher` renueva al 80 % del TTL
  (unas 19 h con 24 h), así que ninguna sesión de 5 minutos queda con una
  credencial vencida. Si Twilio falla, conserva la credencial anterior y
  reintenta cada 60 s, duplicando hasta 15 min.
- **Enganches a Pipecat** (`install_pipecat_ice_hooks`). El runner guarda los
  ICE en `args.ice_servers`, que `/start` lee en cada sesión para el navegador,
  y los copia una vez al `SmallWebRTCRequestHandler` que crea la conexión del
  bot. El enganche hace que `args.ice_servers` sea la lista compartida del
  refresher, y una subclase del handler se registra para recibir cada
  renovación por `update_ice_servers()`. Un test verifica que Pipecat siga
  importando el handler dentro de `_setup_webrtc_routes`; revíselo al
  actualizar Pipecat.
- **Orígenes.** `VOICE_ALLOWED_ORIGINS` se valida y se pasa como
  `PIPECAT_ALLOWED_ORIGINS`. Pipecat trata una lista vacía como "cualquier
  origen", así que una lista vacía, un comodín, una ruta o un esquema distinto
  de `http(s)` detienen el runner. El comando de Compose ya no usa
  `--allowed-origins`, que tendría prioridad sobre la variable.
- **Errores.** Un SID o token ausente o mal formado detiene el runner al
  arrancar. Un fallo de red o un HTTP de Twilio solo registra el estado
  (`HTTP 401`), nunca el SID, el token, la URL ni las credenciales TURN.

## Puesta en marcha

1. Agregue `TWILIO_ACCOUNT_SID` y `TWILIO_AUTH_TOKEN` a `.env`.
2. `brew install cloudflared` y abra dos túneles rápidos en terminales
   separadas. Cada uno imprime una URL `https://…trycloudflare.com` que cambia
   en cada inicio:

   ```bash
   cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8000
   cloudflared tunnel --no-autoupdate --url http://127.0.0.1:7860
   ```

3. En `.env`, con las dos URLs:

   ```bash
   VOICE_TURN_MODE=twilio
   VOICE_ALLOWED_ORIGINS=http://127.0.0.1:8000,http://localhost:8000,https://<api>.trycloudflare.com
   VOICE_PIPECAT_URL=https://<voz>.trycloudflare.com
   ```

4. `docker compose --profile voice up -d --build`. El log de `voice-agent`
   debe mostrar `Voice sessions allowed from: …` y
   `Twilio TURN credentials ready (4 ICE servers, valid for 86400 s)`.
5. Pruebe desde **otra red** (un celular con datos móviles, sin Wi-Fi). Desde
   el mismo Mac o la misma LAN la prueba puede pasar sin usar Twilio. Abra
   `https://<api>.trycloudflare.com/app`, cargue los `.xlsx`, abra 💬, ingrese
   el token y use 🎙. En `chrome://webrtc-internals` (Android o escritorio) el
   par seleccionado debe ser `relay`.
6. Al terminar, cierre los túneles con Ctrl+C y vuelva a `VOICE_TURN_MODE=local`
   y los valores locales de `VOICE_ALLOWED_ORIGINS` y `VOICE_PIPECAT_URL`.

## Seguridad del acceso público

- Use un `ENERGY_TOOLS_API_TOKEN` nuevo y largo solo para la demo, envíe la URL
  y la clave por canales distintos, y rote el token al terminar.
- La cascada de pago solo arranca con un grant de un solo uso que emite
  `energy-api` tras el token; sin él, el runner usa el pipeline mínimo, sin
  proveedores. Los topes `VOICE_BUDGET_USD` y `VOICE_MAX_SESSIONS` siguen
  vigentes. Cada sesión cobra la reserva completa (0,20 USD) aunque dure
  segundos.
- **`/start` exige el grant** (`voice_agent/start_guard.py`). `allowed_origins`
  de Pipecat es solo CORS, así que un middleware ASGI del runner valida
  `body.voice_session_token` y `body.mode` contra
  `POST /voice/sessions/check` de `energy-api`, que **no** consume el grant;
  el bot lo consume después, al recibir la oferta WebRTC. Sin grant vigente,
  `/start` responde 401 y no entrega `iceConfig`, de modo que las credenciales
  TURN de Twilio solo llegan a quien tiene el token. `POST`/`PATCH /api/offer`
  directo responde 403: el cliente usa `/sessions/{id}/api/offer`, que solo
  existe tras un `/start` autorizado. El middleware queda dentro del CORS de
  Pipecat, así que los rechazos llevan cabeceras CORS. Nunca registra el
  grant, el cuerpo ni el SDP.
- Aun así, cierre los túneles cuando no estén en uso.
- Los túneles rápidos son temporales y anónimos. Para una URL fija, use un túnel
  con nombre (cuenta de Cloudflare y dominio propio).

## Límites conocidos

- Hay un solo snapshot en memoria, compartido por todos los usuarios.
- El Mac debe quedar encendido con Docker y los túneles corriendo.
- `turn-local` sigue arrancando en modo `twilio`; no se usa, pero no estorba.
- Alternativas si Twilio no conecta en otra red: forzar
  `iceTransportPolicy: "relay"` en el navegador, el transporte WebSocket de
  Pipecat (sin TURN, audio menos fluido) o un servidor con coturn propio.
