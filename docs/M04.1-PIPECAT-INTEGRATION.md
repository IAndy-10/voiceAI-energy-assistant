# M04.1 — Integración local Pipecat / Energy Tools

## Objetivo y decisión

M04.1 prepara una integración de voz sin alterar M03.7. Se selecciona la alternativa **B: un adaptador HTTP autenticado** (`voice_agent/energy_api.py`) que consume la API FastAPI existente. Es la opción adecuada para futuros contenedores separados: Pipecat no comparte memoria con `energy-api`, no accede al snapshot ni duplica cálculos, y la API conserva el único contrato de datos.

La alternativa A (invocar `EnergyTools` directamente) sirve sólo si ambos componentes viven en el mismo proceso; comparte el repositorio en memoria y acopla el proceso de voz al backend. Se descarta para el despliegue objetivo.

    Browser / transporte de voz
                 |
          Pipecat pipeline (M04.2)
                 |
      VoiceEnergyAdapter + Bearer local
                 |
       FastAPI energy-api :8000
                 |
       SnapshotRepository en memoria
                 |
       resultados calculados por dashboard

| Componente | Responsabilidad |
| --- | --- |
| Dashboard | Lee Excel privado en el navegador y genera el snapshot ya calculado. |
| `energy-api` | Valida y mantiene un único snapshot en memoria; ejecuta las seis tools. |
| `VoiceEnergyAdapter` | Autentica y transforma llamadas de voz en los endpoints HTTP existentes. |
| Pipecat (M04.2) | Orquesta audio, contexto, interrupciones y el registro de handlers, sin acceder a Excel/snapshots. |

## Contrato actual

Todos requieren `Authorization: Bearer <token>` y retornan el mismo sobre: `status`, `data`, `period`, `unit`, `source`, `warnings`.

| Tool | Endpoint HTTP | Argumentos |
| --- | --- | --- |
| `get_overview(year)` | `GET /energy/overview` | `year` (2000–2100) |
| `get_store(name, year)` | `GET /energy/stores/{name}` | `name`, `year` |
| `rank_stores(metric, order, top_n)` | `GET /energy/stores/ranking` | métrica `cost`, `kwh`, `increase_abs` o `increase_pct`; `asc`/`desc`; 1–100 HTTP (la tool del agente limita 1–20) |
| `get_solar(plant)` | `GET /energy/solar` | `plant` opcional |
| `get_chiller(year)` | `GET /energy/chiller` | `year` opcional |
| `get_data_info()` | `GET /energy/data-info` | sin argumentos |

El adaptador conserva esos metadatos y devuelve un resultado seguro con `warnings` para timeout, conexión, HTTP, configuración y protocolo. Nunca registra token, URL con datos, snapshot ni cuerpo de respuestas.

## Snapshots y autenticación

`POST /snapshot` valida el JSON Pydantic y lo mantiene exclusivamente en la memoria de `energy-api`; al recrear ese servicio debe cargarse de nuevo. El servicio de voz recibe sólo `VOICE_ENERGY_API_BASE_URL` (por defecto `http://127.0.0.1:8000` para desarrollo), `VOICE_ENERGY_API_TOKEN` y un timeout. El valor de `VOICE_ENERGY_API_TOKEN` debe coincidir con el valor local de `ENERGY_TOOLS_API_TOKEN` configurado en `energy-api`; ambos se mantienen fuera de Git. En una red Compose futura, use `http://energy-api:8000` y una variable/secret local; no monte `Datos/` ni copie snapshots al contenedor de voz.

Solicitud sintética equivalente a `adapter.get_overview(2025)`:

```http
GET /energy/overview?year=2025
Authorization: Bearer <token-local-no-versionado>
Accept: application/json
```

Ejemplo sintético de respuesta:

```json
{
  "status": "ok",
  "data": {"kwh": {"value": 1200, "display": "1,2 MWh"}},
  "period": 2025,
  "unit": "CLP y kWh",
  "source": ["demo-costos.xlsx"],
  "warnings": ["2025 es un año parcial; no debe compararse con un año completo."]
}
```

## Pipecat: preparación, no implementación de voz

No se añade `pipecat-ai` en M04.1: todavía no se ha elegido proveedor STT, LLM o TTS, ni se instala infraestructura de audio. La versión publicada observada durante esta auditoría fue `pipecat-ai` **1.14.0**; M04.2 debe fijar y validar explícitamente la versión elegida antes de usar su API. La documentación oficial actual recomienda **SmallWebRTC** para desarrollo local/autohospedado y WebRTC para voz navegador-servidor; WebSocket queda para texto o servidor-a-servidor. M04.2 debe seleccionar STT, LLM, TTS, transporte, VAD/interrupciones, política de contexto, timeout y presupuesto de latencia.

El siguiente es **pseudocódigo**, no una API de Pipecat ejecutable. Debe ajustarse contra la versión instalada durante M04.2:

```python
# PSEUDOCÓDIGO: registrar handlers con el LLMService de Pipecat elegido.
adapter = VoiceEnergyAdapter()

async def energy_tool_handler(function_name: str, arguments: dict) -> dict:
    # Sólo se permiten los seis nombres del adaptador.
    return adapter.call(function_name, **arguments)
```

Pipecat documenta eventos de inicio de function calls y errores/timeout de LLM; esos eventos se conectarán a trazas seguras en M04.2, sin loguear contenido energético. Referencias: [paquete 1.14.0](https://pypi.org/project/pipecat-ai/1.14.0/), [transportes](https://docs.pipecat.ai/client/concepts/choosing-a-transport) y [eventos de servicio](https://docs.pipecat.ai/server/utilities/service-events).
