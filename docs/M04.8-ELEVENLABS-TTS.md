# M04.8 — TTS con ElevenLabs y medición de latencia

## Alcance

El TTS de la cascada de voz es intercambiable. OpenAI (`gpt-4o-mini-tts`) sigue
siendo el valor por defecto; ElevenLabs se activa con
`VOICE_TTS_PROVIDER=elevenlabs`. STT (`gpt-transcribe`) y LLM siguen en OpenAI.
El diseño sigue el del proyecto de referencia *voiceAI-personal-assistant*:
un interruptor de proveedor, el SDK importado solo cuando se usa y
`ElevenLabsTTSService` de Pipecat 1.14.0 configurado con `Settings(...)`.

## Configuración

| Variable | Por defecto | Uso |
| --- | --- | --- |
| `VOICE_TTS_PROVIDER` | `openai` | `openai` o `elevenlabs`; otro valor impide iniciar la sesión con IA |
| `ELEVENLABS_API_KEY` | — | Obligatoria con `elevenlabs`; Compose la entrega solo a `voice-agent` |
| `ELEVENLABS_MODEL` | `eleven_flash_v2_5` | Modelo multilingüe de menor latencia |
| `ELEVENLABS_VOICE` | George (`JBFqnCBsd6RMkjVDRZzb`) | Voz prediseñada; funciona en el plan gratuito |

- `create_tts()` en `voice_agent/voice_pipeline.py` elige el servicio. Con
  ElevenLabs fija `Language.ES` y conserva `spoken_transform` para que unidades
  y símbolos se pronuncien como palabras. ElevenLabs no acepta instrucciones de
  estilo, así que `TTS_INSTRUCTIONS` solo aplica a OpenAI.
- `validate_for_real_use()` rechaza la sesión, sin exponer claves, si falta la
  key de ElevenLabs o el proveedor no es válido. El panel muestra el aviso
  `voice_unavailable`.
- El log de inicio indica `tts=<proveedor>/<modelo>/<voz>`, nunca la key.
- El extra `elevenlabs` se agregó a `voice_agent/requirements-voice.txt`;
  reconstruya `voice-agent` (o reinstale el `.venv` de Windows).

## Presupuesto y datos

- La reserva local `VOICE_SESSION_BUDGET_USD` se mantiene antes de crear
  cualquier servicio, pero ElevenLabs cobra créditos de su plan y el ledger no
  los controla. El límite real del TTS es la cuota del plan.
- Con ElevenLabs activo, el texto de cada respuesta hablada (cifras agregadas
  devueltas por las herramientas) se envía también a ElevenLabs. Nunca se envían
  snapshots ni Excel.

## Medición de latencia

El runner usa `PipelineParams(enable_metrics=True)`, que registra en DEBUG el
tiempo al primer byte (TTFB) de cada servicio. `scripts/voice_latency.py` lee
esas líneas y resume n, mediana, p90 y rango por servicio:

```bash
docker compose logs --since 30m voice-agent | python scripts/voice_latency.py
```

Primera comparación (macOS, Docker, 3–4 de noviembre de 2026; muestras chicas):

| Servicio | OpenAI TTS | ElevenLabs Flash v2.5 |
| --- | --- | --- |
| TTS, mediana (n) | 1,030 s (12) | **0,229 s** (6) |
| TTS, p90 | 1,620 s | **0,261 s** |
| TTS, rango | 0,420–1,788 s | 0,201–0,279 s |
| STT `gpt-transcribe`, mediana | 1,343 s | 1,062 s |
| LLM `gpt-6-luna`, mediana | 0,968 s | 0,828 s |

STT y LLM no cambian con el proveedor de TTS; sus diferencias son variación de
red y carga. El TTS bajó unos 0,8 s por respuesta y se volvió estable. Sumando
medianas, un turno pasó de ~3,3 s a ~2,1 s (aproximación: excluye la espera del
VAD y el LLM se llama dos veces cuando usa una herramienta). Ahora el mayor
componente es el STT por segmentos; la siguiente mejora sería un STT en streaming.

## Diagnóstico

- Si ElevenLabs rechaza la solicitud (voz inexistente, voz de la Voice Library
  en plan gratuito, key sin permiso de text-to-speech), Pipecat solo registra
  `TTS context ... completed with no audio`. Vacíe `ELEVENLABS_VOICE` para
  volver a George y verifique los permisos de la key.
- Docker Desktop no relee `.env` con Stop/Play: tras cambiar el proveedor, use
  `docker compose --profile voice up -d --force-recreate voice-agent`.
